# F0.1 — pnpm workspace monorepo scaffold

- **Status:** planned
- **Milestone:** M0 · **Level:** infra
- **Depends on:** none

## 1. Purpose (abstract)

Establish the empty frame the whole product is built into: a pnpm-workspace monorepo with a consistent home for every later package and app. Before any IR types, adapters, CLI, MCP server, or dashboard can exist, there must be a single repository skeleton that resolves cross-package dependencies and shares one TypeScript baseline. This feature adds no product behavior — it adds the structural contract that every subsequent feature inherits.

## 2. Contract & boundary

This is **infra-level scaffolding** that sits above both core and adapters; it contains no framework knowledge and no runtime logic.

**Exposes:**
- A directory layout — `packages/` (e.g. `@uigraph/core`, future adapters, CLI, MCP), `apps/` (e.g. dashboard), `examples/` (sample-react-app, sample-angular-app).
- `pnpm-workspace.yaml` declaring the member globs (`packages/*`, `apps/*`, `examples/*`).
- A shared base `tsconfig.base.json` that package-level tsconfigs `extends`.
- A root `package.json` with `private: true`, the pnpm version pin, and workspace-wide scripts.

**Depends on:** only the host toolchain (Node + pnpm). Nothing inside the repo.

## 3. Abstract design

**Input:** a clean checkout. **Output:** a workspace where `pnpm install` resolves all members and `pnpm -r list` enumerates them.

Key decisions:
- **pnpm workspaces** for `workspace:*` protocol cross-linking (later `@uigraph/cli` depends on `@uigraph/core`).
- **Single base tsconfig** so strictness lives in exactly one place (F0.2 hardens it); package configs only set `extends`, `rootDir`/`outDir`, and references.
- **Three top-level buckets** keep publishable libraries (`packages/`), runnable apps (`apps/`), and golden fixtures (`examples/`) cleanly separated.

Trade-off: scaffolding member packages with only a `package.json` (no source yet) keeps this feature thin and lets each later feature own its real contents, at the cost of placeholder packages in the tree.

## 4. Data shapes

This feature owns no IR types. It owns only repo config files (`pnpm-workspace.yaml`, `tsconfig.base.json`, root `package.json`). Shared IR types are defined later in `30-ir-spec-v0.md` (F0.4) and are out of scope here.

## 5. Test strategy (write these first)

1. `pnpm install` exits zero on a clean checkout with no warnings that block resolution.
2. `pnpm -r list` enumerates every declared workspace member; assert the expected package directories appear.
3. Each declared member directory is discoverable as a workspace member (covered by the glob in `pnpm-workspace.yaml`).
4. A throwaway package whose tsconfig `extends` `tsconfig.base.json` inherits the base compiler options (inheritability check).
5. Root `package.json` is `private: true` and exposes the agreed workspace scripts.

## 6. Self-check / acceptance criteria

- `pnpm install` completes with **zero errors**.
- `pnpm -r list` enumerates **all declared workspace packages**.
- A package extending `tsconfig.base.json` compiles using the inherited options.

## 7. Soundiness / open questions

- None. No dynamic targets or guards — purely structural. Member packages are placeholders until their owning features populate them.
