# F0.4 — Framework-agnostic IR types (guarded modal LTS)

- **Status:** planned
- **Milestone:** M0 · **Level:** L0
- **Depends on:** F0.3

## 1. Purpose (abstract)

Define, in TypeScript, the framework-neutral intermediate representation that the entire product speaks: a guarded labeled transition system with modal edge labels (dossier §5.3). These types are the single shared vocabulary every adapter targets and every op, the MCP server, and the dashboard consume. Encoding them once, with zero framework knowledge, is what keeps `@ui-graph/core` framework-agnostic and lets new frameworks arrive as adapters that never edit the core.

## 2. Contract & boundary

**Lives in `@ui-graph/core`** (framework-agnostic — no React/Angular imports, direct or transitive). This feature owns the *type layer only*; ops, schema, and algorithms are later M1 features.

Exposes (per `docs/30-ir-spec-v0.md`, which this feature implements verbatim):
- Enums: `Modality = 'must'|'may'|'unknown'`, `Source = 'static'|'manual'|'runtime'`, `NodeKind`.
- Interfaces: `GraphNode`, `GraphEdge`, `Witness`, `UiGraph`, `Overlay`.

Depends on: F0.3 (the self-healing check gate) only as the green-gate harness, and the F0.1/F0.2 strict-TS toolchain it builds on. No runtime dependencies.

## 3. Abstract design

Input: nothing at runtime — this is a pure type/declaration module exporting the IR shapes (and the string-literal-union enums, which exist at value level for exhaustiveness). Output: a typed surface importable as `@ui-graph/core` that downstream packages build against.

Key decisions:
- **Modality is a closed string union**, not an open string, so a `switch` over it can be made exhaustive (`never` check) — adapters and the dashboard get compile-time coverage of `must`/`may`/`unknown`.
- **`source` and `confidence` are per-edge**, never per-graph, because provenance (static/manual/runtime) and certainty (0..1) are properties of an individual transition's proof, which the golden invariant (F1.3) later enforces.
- **Guard/effect are opaque `string | null`** — symbolic source text, never evaluated (legibility over decidability, dossier §6 of the spec).
- The types carry **no framework fields**; how a `GraphEdge` gets populated is the adapter's job, identical shape regardless of React or Angular.

Trade-off: keeping enums as value-level unions (not TS `enum`s) avoids a runtime enum object and erased-const pitfalls while still giving exhaustiveness.

## 4. Data shapes

This feature owns no new shapes beyond what `docs/30-ir-spec-v0.md` already specifies; it is the canonical TS implementation of that spec. See the spec for `Modality`, `Source`, `NodeKind`, `GraphNode`, `Witness`, `GraphEdge`, `UiGraph`, and `Overlay`. Nothing is redefined or extended here.

## 5. Test strategy (write these first)

1. **Valid construction.** Build an in-memory `UiGraph` literal with three nodes and edges covering all three modalities (`must`, `may`, `unknown`); it type-checks under strict TS.
2. **Per-edge source coverage.** Construct edges with each `Source` (`static`, `manual`, `runtime`) and assert each is assignable to `GraphEdge['source']`.
3. **Confidence is numeric.** Assert `confidence` accepts `0`, `1`, and a mid value, and rejects non-numbers at the type level.
4. **Modality exhaustiveness.** A helper that `switch`es over `Modality` with a `never` default fails to compile if a case is dropped — a type-level test proving the union is closed.
5. **Source exhaustiveness.** Same `never`-default exhaustiveness check over `Source`.
6. **Overlay shape.** A sample `Overlay` with one `addedEdge` marked `source: 'manual'` type-checks.
7. **No framework imports.** A static check (grep/import scan in test or lint) asserts the `core` type module imports nothing from `react`, `react-dom`, `@angular/*`.

## 6. Self-check / acceptance criteria

- The IR types compile under strict TS (`tsc --noEmit` green via the F0.3 gate).
- A sample in-memory `UiGraph` with `must`/`may`/`unknown` edges and per-edge `source` + `confidence` type-checks.
- `@ui-graph/core` has zero React/Angular dependencies (no such entries in `package.json`; no transitive framework import in the type module).
- The F0.3 gate (typecheck + lint + test) exits green.

## 7. Soundiness / open questions

- None for v1. `confidence` is typed as `number`, not a refined `0..1` brand; the numeric-range invariant (`0 ≤ confidence ≤ 1`) is enforced at runtime by `validate()` in F1.3, not at the type level — an accepted, deliberate split between shape (here) and value invariants (later).
