# F4.2 — CLI map --adapter command

- **Status:** planned
- **Milestone:** M4 · **Level:** L1
- **Depends on:** F4.1

## 1. Purpose (abstract)

Make extraction usable from the command line: `uigraph map --adapter react|angular <dir>` is the primary command that turns a real project into a serialized graph artifact. It selects the named adapter, runs its `extract` over the target directory, and writes the resulting `ui-graph.json` (and the soundiness report) to disk. This is the end-user on-ramp that converts the M2/M3 adapter pipelines into a one-line tool, and it is the same command later reused against the real-world validation target (F7.1).

## 2. Contract & boundary

**Lives in `@uigraph/cli`** (the `core, adapters` layer per `docs/10-architecture.md` §5). The CLI is the only place allowed to know *both* adapters by name; it maps the `--adapter` string to a concrete adapter instance and otherwise speaks only core IR. `@uigraph/core` stays framework-agnostic and the adapter packages are imported solely here.

Exposes: the `map` subcommand handler registered on the F4.1 dispatcher, with the shape `map(adapterName: 'react' | 'angular', dir: string, opts: { out?: string }) -> exit code`. On success it writes `ui-graph.json` and `ui-graph.soundiness.json`; on an unknown adapter or missing/invalid `<dir>` it errors with a clear message and a non-zero exit.

Depends on:
- **F4.1** CLI scaffold — argument parsing, help, dispatch, and the unknown-command/missing-arg error path this handler plugs into.
- `@uigraph/adapter-react` (F2.7) and `@uigraph/adapter-angular` (F3.5) for `extract(projectDir)` plus the per-extraction soundiness report.
- `@uigraph/core` `save` (F1.2, validates against the JSON schema on write) and the IR/`UiGraph` shape (F0.4, `docs/30-ir-spec-v0.md`).

## 3. Abstract design

Input: an adapter name and a project directory (plus an optional output path). Output: two files on disk and an exit code.

Flow: resolve `--adapter` to an adapter via a small static name→adapter registry (`{ react, angular }`); reject any other name *before* doing filesystem work. Validate `<dir>` exists. Call `adapter.extract(dir)`, which returns the `UiGraph` and the soundiness report. Write the graph with core `save` (so the schema is enforced on the way out — a malformed graph fails the command rather than landing on disk) and write the report alongside it. Print a short summary (node/edge counts, resolved-vs-over-approximated tally) and exit 0.

Key decisions:
- **The name registry is the only framework branch in the whole product.** Adding an adapter is one map entry, never a change to core or to other commands (dossier §17, architecture §2).
- **Default output location is the target dir**: `<dir>/ui-graph.json` and `<dir>/ui-graph.soundiness.json`, matching the `ui-graph.json` base-artifact convention (architecture §6); `--out` overrides the directory.
- **Validation happens via `save`, not a second code path** — `map` does no schema work of its own (DRY against F1.1/F1.2).

Trade-off: the adapter list is a hardcoded literal rather than dynamic plugin discovery — YAGNI for v1's two adapters; a registry indirection would remove no real duplication.

## 4. Data shapes

None new. `map` consumes the existing `UiGraph` (`docs/30-ir-spec-v0.md`) and the adapter-owned soundiness report (defined by F2.6/F3.x); it adds no IR type and extends none. It only orchestrates `extract` → `save` → file write.

## 5. Test strategy (write these first)

1. **React golden.** `map --adapter react examples/sample-react-app` writes `ui-graph.json` that is schema-valid and equals the committed React golden under canonical comparison (modality, source, guard, witness per edge).
2. **Angular golden.** `map --adapter angular examples/sample-angular-app` writes `ui-graph.json` matching the committed Angular golden under canonical comparison.
3. **Soundiness report emitted.** Each run also writes `ui-graph.soundiness.json` next to the graph, and it parses and lists the expected over-approximated/unresolved cases.
4. **Schema validity asserted independently.** The written `ui-graph.json` validates against the F1.1 JSON schema (not just golden equality).
5. **Unknown adapter errors.** `map --adapter vue <dir>` exits non-zero with a clear message naming the unknown adapter and does **not** write any file.
6. **Missing/invalid dir errors.** A non-existent `<dir>` exits non-zero with a clear message and writes nothing.
7. **`--out` override.** A custom output directory is honored for both files; the target dir is left untouched.

## 6. Self-check / acceptance criteria

- `uigraph map --adapter react examples/sample-react-app` emits a schema-valid `ui-graph.json` matching the React golden.
- The Angular equivalent emits a schema-valid `ui-graph.json` matching the Angular golden.
- Each run also writes the soundiness report alongside the graph.
- An unknown `--adapter` value and a missing `<dir>` each exit non-zero with a clear message and write no graph file.
- The F0.3 gate (typecheck + lint + test) exits green.

## 7. Soundiness / open questions

- **Adapter-level soundiness is inherited, not added here** — `map` faithfully writes whatever over-approximated/unresolved cases the adapter declares (F2.6/F3.x); it neither resolves nor hides them.
- **Overwrite behavior of an existing `ui-graph.json`** is a write (the base is reproducible from `repo@commit`, so re-mapping is expected); no merge with a prior file is attempted in v1.
- **Overlay and observation log are out of scope** — `map` only produces the static base graph; the sidecar overlay and `observations.log.jsonl` are written by other paths (F4.4, F5.x).
