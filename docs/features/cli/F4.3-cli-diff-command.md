# F4.3 — CLI diff command

- **Status:** planned
- **Milestone:** M4 · **Level:** L1
- **Depends on:** F4.2 (CLI `map --adapter` command)

## 1. Purpose (abstract)

`uigraph diff <a> <b>` puts behavioral-impact analysis one command away. It loads
two serialized `ui-graph.json` files and prints the core `diff` — added, removed,
and changed nodes and edges, down to per-edge modality and guard changes — in a
form a human can read at a glance instead of eyeballing raw JSON churn. This is
the command-line face of the "lockfile for the app's behavior" (dossier §5.2):
diff two graphs from two commits and see exactly what the change did to the
transition structure.

## 2. Contract & boundary

**Lives in `@ui-graph/cli`** — the user-facing entry point. It owns argument
handling, filesystem reads, and human-readable rendering; it owns **no** graph
semantics. All comparison logic is delegated to `@ui-graph/core`. The CLI stays
framework-agnostic: it never imports an adapter (diff operates on already-extracted
graphs, so no framework knowledge is involved).

Exposes the `diff` subcommand registered on the F4.1 dispatcher:

```
uigraph diff <a> <b>     # <a> = before graph file, <b> = after graph file
```

Depends on: F4.1 dispatch/arg-parsing, and from `@ui-graph/core` the pure
`load(json)` (F1.2) and `diff(a, b): GraphDiff` (F1.5) ops over the IR in
`30-ir-spec-v0.md`. Nothing depends on this command.

## 3. Abstract design

**Input → output.** Two file paths → exit 0 plus a rendered report on stdout.
The handler reads each file, calls `load` on each (so a malformed or schema-invalid
file is rejected at the boundary with a clear message and a non-zero exit, never a
silent half-diff), calls core `diff(a, b)`, then renders the resulting `GraphDiff`.

**Rendering.** A compact, deterministic, line-oriented report grouped by bucket:
added/removed nodes, added/removed edges, and changed edges. Each changed edge
lists its per-field `{ before → after }` pairs, so `modality` (`must → may`) and
`guard` (`"isAuthenticated" → "user.role === 'admin'"`) changes are read edge by
edge. An empty diff (all five buckets empty) prints a single explicit no-change
line. Output is sorted by id (inherited from core `diff`) so it is stable and
snapshot-friendly.

**Key decisions / trade-offs.** The CLI is a thin rendering shell — zero diff
logic duplicated from core (DRY: one diff implementation, F1.5). Default output is
the readable text form; a `--json` flag emitting the raw `GraphDiff` is a possible
later addition, out of v1 scope (YAGNI). Guard text is printed verbatim, never
evaluated (legibility over decidability, IR spec §6).

## 4. Data shapes

This feature owns **no** IR or diff types. It consumes `UiGraph` and `GraphDiff`
(with `ChangedEdge` / `EdgeFieldChange`) unchanged from `@ui-graph/core`
(`30-ir-spec-v0.md`, F1.5). Its only surface is the rendered text format, which is
a presentation of those types, not a new type.

## 5. Test strategy (write these first)

1. **Identical files → no-change result.** `uigraph diff g.json g.json` exits 0 and
   prints the explicit empty/no-change line, no bucket sections.
2. **Seeded delta fixture pair.** Two fixture files differing by one added node, one
   removed edge, and one modality change → output contains exactly those three
   deltas and nothing spurious.
3. **Modality change rendered.** A `must → may` edge prints a changed-edge line whose
   field list shows `modality: must → may`.
4. **Guard change rendered.** A guard text change (and `null → text`) prints the
   `guard` before/after symbolic text.
5. **Added/removed nodes and edges.** Each bucket is rendered under its own labeled
   section with the affected ids.
6. **Deterministic output.** Re-running on the same pair yields byte-identical output
   (sorted by id); golden-snapshot the rendered text.
7. **Malformed/invalid input.** A schema-invalid or unreadable file exits non-zero
   with a clear message and prints no partial diff.

## 6. Self-check / acceptance criteria

- `uigraph diff` on two known graph files reports the correct node/edge/modality
  deltas, with per-edge `modality` and `guard` changes shown as `before → after`.
- `uigraph diff` on two identical files reports no changes (single explicit line,
  exit 0).
- An unreadable or schema-invalid input file produces a clear error and a non-zero
  exit, never a partial result.
- Rendered output is deterministic and matches the committed golden snapshot.
- All diff semantics come from `@ui-graph/core` (no comparison logic in the CLI);
  the CLI imports no adapter.
- `node scripts/check.mjs` prints `CHECK GREEN` (typecheck + tests + lint) with no
  sibling regression.

## 7. Soundiness / open questions

- **Text-only output in v1.** No `--json` machine-readable mode yet; deferred until a
  consumer needs it (the MCP `diff` tool, F5.5, covers programmatic access).
- **No node field-diff.** Inherited from core `diff` (F1.5): changed node attributes
  on a stable id are not reported in v1, only node add/remove. The renderer surfaces
  exactly what core reports.
- **Rename reads as remove+add.** Inherited from core: an `id` change shows as a
  removal plus an addition, with no rename heuristic.
