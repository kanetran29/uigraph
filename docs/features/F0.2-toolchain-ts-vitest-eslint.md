# F0.2 — Shared TypeScript, vitest, and eslint toolchain

- **Status:** planned
- **Milestone:** M0 · **Level:** infra
- **Depends on:** F0.1

## 1. Purpose (abstract)

Establish one shared developer toolchain — strict TypeScript, vitest, and eslint — configured once at the workspace root and inherited by every package. This gives the whole monorepo a uniform, green-by-default baseline so each later feature can run tests-first under vitest, typecheck under strict TS, and lint cleanly without re-configuring its tooling. It is the precondition that makes the F0.3 self-healing check gate meaningful: there must be a real typecheck, test, and lint to run.

## 2. Contract & boundary

This is **infra**, not a publishable package: it owns root config and root `package.json` scripts, and lives entirely outside `@uigraph/core` / the adapters. It exposes three repo-root scripts as its public surface:

- `pnpm typecheck` → fans out `tsc --noEmit` over members (`pnpm -r --if-present run typecheck`).
- `pnpm test` → fans out vitest over members (`pnpm -r --if-present run test`).
- `pnpm lint` → `eslint .` across workspace source.

It also exposes inheritable artifacts: `tsconfig.base.json` (strict compiler options), root flat `eslint.config.mjs`, and the workspace `catalog:` entries for `vitest`/`typescript`. **Depends on** F0.1 (the pnpm workspace, member layout, and base tsconfig frame) and nothing else. It is framework-agnostic and ships no React/Angular knowledge.

## 3. Abstract design

Configure-once, inherit-everywhere. The root holds the single source of truth; each package contributes only a tiny `tsconfig.json` that `extends` the base and per-package `typecheck`/`test` scripts, so the `-r --if-present` fan-out picks them up automatically as packages are added.

- **Input:** a clean checkout with the F0.1 workspace frame and one trivial sample test plus a sample source file as the baseline subject.
- **Output:** `typecheck`, `test`, and `lint` each exit `0` on that baseline.

Key decisions: strict TS (`strict`, `noUncheckedIndexedAccess`, `verbatimModuleSyntax`, `noEmit`) for an honest type signal; **flat** eslint config on `typescript-eslint` recommended (non-type-checked for speed), with `examples/**` and `apps/dashboard/**` ignored since fixtures and the Vite app carry their own concerns; vitest as the single runner so no Jest/runner split emerges. Trade-off: non-type-checked lint trades some rule depth for fast, dependency-light linting — `tsc` already provides the deep type signal, so the overlap would be redundant (DRY).

## 4. Data shapes

None. This feature owns configuration and scripts only; it defines no IR or runtime types and does not touch the shared IR (`docs/30-ir-spec-v0.md`).

## 5. Test strategy (write these first)

1. A trivial sample test (e.g. `expect(1 + 1).toBe(2)`) runs green under `vitest run`, proving the runner and config resolve in a workspace member.
2. `pnpm typecheck` (`tsc --noEmit`) passes on the baseline workspace with a sample source file under strict options — no type errors, no emit.
3. `pnpm lint` (`eslint .`) reports zero errors/warnings on the baseline source.
4. Negative sanity (manual, not committed): a deliberate type error fails typecheck and a lint violation (e.g. unused non-`_` var) fails lint — confirming the tools actually have teeth, not vacuously passing on no files.

## 6. Self-check / acceptance criteria

- Running the test, typecheck, and lint scripts at the repo root each exit `0` on a clean checkout.
- `pnpm test`, `pnpm typecheck`, and `pnpm lint` are wired in root `package.json` and resolve member scripts via the `-r --if-present` fan-out.
- Strict TS options are active in `tsconfig.base.json` and inherited; eslint runs flat config and excludes `examples/**` and `apps/dashboard/**`.
- The baseline sample test is discovered and green under vitest.

## 7. Soundiness / open questions

None. This is a deterministic infra feature with no dynamic-target or guard concerns; type-checked lint can be added later if a rule needs type information, but it is out of v1 scope (YAGNI).
