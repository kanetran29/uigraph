# F3.2 — Angular RouterModule/Routes extraction

- **Status:** planned
- **Milestone:** M3 · **Level:** L1
- **Depends on:** F3.1 (sample-angular-app golden fixture), F1.6 (graph algorithms: reachability + plan_path BFS)

## 1. Purpose (abstract)

This feature implements the **route side** of `@uigraph/adapter-angular`: it reads an Angular project's `RouterModule`/`Routes` configuration and emits one IR `route` node per declared route, resolving `path`, `component`, and nested `children` into parent/child structure. It produces the **bounded node inventory** of declared routes — the finite codomain that later edge extraction (F3.3) over-approximates non-literal navigations against. It is the Angular analogue of F2.2 (React route-node extraction): nodes only, no edges yet.

## 2. Contract & boundary

Lives in the **adapter package `@uigraph/adapter-angular`**, never in `@uigraph/core` — all Angular and TS-compiler knowledge is confined here (`40-adapter-contract.md §7`). It depends on `@uigraph/core` only for the shared IR types (`UiGraph`, `GraphNode`) and the `Adapter` contract.

**Exposes** (consumed by F3.3–F3.5): a route-extraction step that, given a project dir and the `AdapterContext` (shared `tsProject()` / cached `readFile`), returns the route-node inventory plus the parent/child relation.

```ts
// internal to the adapter; the public seam is Adapter.extract (F3.5)
function extractRouteNodes(ctx: AdapterContext, projectDir: string): RouteExtraction;
```

**Depends on:** F3.1 for the golden fixture and its known-route manifest; F1.6 indirectly for the downstream consumers of the node set. It does **not** emit edges (F3.3), guards (F3.4), or assemble the full `extract` pipeline (F3.5).

## 3. Abstract design

**Input → output.** Input: the project source via `ctx.tsProject()`. Output: a list of `route` `GraphNode`s + a parent→children map, derived from the `Routes` array(s) wired into `RouterModule.forRoot(...)` / `forChild(...)`.

**Approach.** Walk the TS AST for array literals passed to `RouterModule.forRoot`/`forChild` (and exported `Routes`-typed consts they reference). For each route object literal, read the `path` string, resolve `component` to its class/source file, and recurse into `children`. One node per route; the node `route` field is the **full path from the config root** (parent paths joined), so nesting is reflected in the path while parent/child identity is tracked separately for F3.3.

**Key decisions / trade-offs.**
- **L1 minimum: routes only.** Per the capability table (`40-adapter-contract.md §3`), Angular's floor is route nodes; this feature delivers exactly that, no edges.
- **Static, literal config only.** Resolve `path`/`component`/`children` from literal object structure. Programmatically built or spread route arrays are recorded as a soundiness gap, not silently dropped.
- **Bounded codomain.** The declared route set is the finite target space for F3.3's over-approximation; completeness of *this* set is what makes that sound.
- **Node ids/labels** are derived deterministically (from full path / component name) so the F3.5 golden compares stably under canonical ordering.

## 4. Data shapes

This feature defines **no new IR types** — it populates the shared `GraphNode` (`kind: 'route'`, `route`, `componentPath`, `label`) from `30-ir-spec-v0.md`. It owns one local, adapter-internal shape for the route side's output:

```ts
interface RouteExtraction {
  nodes: GraphNode[];                 // kind: 'route'
  parentOf: Map<string, string>;     // childNodeId -> parentNodeId (nesting)
}
```

`parentOf` is internal scaffolding for F3.3 (it bounds where child navigations land); it is not serialized into the `UiGraph`.

## 5. Test strategy (write these first)

1. **Flat routes → nodes.** A top-level `Routes` array of literal `{ path, component }` entries yields exactly one route node per entry, with the correct `route` path and resolved `componentPath`.
2. **Nested children → nodes + parentage.** A route with `children` produces a node per child whose `route` is the **joined parent + child path**, and whose entry in `parentOf` points to the correct parent node.
3. **Multi-level nesting.** Grandchild routes resolve their full path through both ancestors and chain parentage correctly.
4. **`forRoot` and `forChild`.** Routes wired via both `RouterModule.forRoot(...)` and `forChild(...)` are discovered; an exported `const routes: Routes = [...]` referenced by either is followed.
5. **Exhaustive known set (golden).** On `examples/sample-angular-app`, the extracted route-node set equals the fixture manifest's known routes exactly — no missing route, no spurious node.
6. **Empty/`''` and `redirectTo` paths.** Index (`path: ''`) and redirect-only entries are handled per the manifest's documented expectation without crashing.

## 6. Self-check / acceptance criteria

- Route extraction on `examples/sample-angular-app` yields **exactly the known set** of route nodes, **including nested children**, with correct paths and parent/child relationships (tests 1–5 green).
- All emitted nodes are `kind: 'route'`; **no edges** are produced by this feature.
- `@uigraph/adapter-angular` imports `@uigraph/core` for IR types only; no Angular/TS-compiler type leaks into the core (`40-adapter-contract.md §7`).
- The self-healing gate (`scripts/check.mjs`) passes with the route-extraction code and tests in the tree.

## 7. Soundiness / open questions

- **Non-literal route config.** Routes assembled programmatically, spread from another array, or built by a function are recorded as a soundiness-report gap (F3.5 wiring), not silently dropped.
- **`loadChildren` / lazy modules.** Lazy-loaded route boundaries are out of scope for v1 route nodes; the lazy boundary is declared as an unresolved case rather than followed.
- **Path/route-pattern normalization** (matrix params, wildcards `**`, `redirectTo` targets) is captured as raw symbolic path text; precise matching semantics are not modeled and the convention is finalized alongside the F3.5 golden.
