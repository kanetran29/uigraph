# F3.5 — Validate Angular adapter against sample golden graph

- **Status:** planned
- **Milestone:** M3 · **Level:** L2
- **Depends on:** F3.4

## 1. Purpose (abstract)

F3.2–F3.4 built the Angular adapter's pieces — route nodes, navigation edges, and
`canActivate` guard may-edges — but no feature has yet asserted the *whole*
`extract(projectDir)` pipeline reproduces the fixture's known transition graph.
This feature is that trust checkpoint: it assembles the full Angular extract
pipeline and compares its output, under canonical equality, against the
hand-authored golden graph of `examples/sample-angular-app`. It clears Rung 3 and
Rung 4 of the validation ladder — Angular green on its own, then both adapters
green together — proving the framework-agnostic IR holds across two frameworks.

## 2. Contract & boundary

This feature lives in the **adapter** package `@uigraph/adapter-angular`, not the
core. It owns the package's `extract(projectDir): UiGraph` entry point that wires
F3.2–F3.4 into one pass, plus the committed golden artifact for the sample app.

**Exposes:**
- `extract(projectDir)` — the v1-required `Adapter` method (F0.5), now complete
  for Angular: route extraction → navigation edges → guard may-edges, emitting one
  canonical `UiGraph`.
- A committed `examples/sample-angular-app/golden/ui-graph.json` — the expected
  graph, the oracle the test diffs against.

**Depends on:** F3.4 (and transitively F3.1–F3.3) for the extraction stages;
`@uigraph/core` for the `UiGraph`/`Adapter` types (F0.4/F0.5), `validate` (F1.3),
canonicalization/`load` (F1.2), and `diff` (F1.5) used to compare. The adapter
imports the core; the core never imports the adapter.

## 3. Abstract design

Input: the `examples/sample-angular-app` project directory. Output: a single
`UiGraph` whose nodes, edges, modalities, sources, guards, and witnesses equal the
committed golden.

Key decisions:
- **Assembly, not new extraction logic.** This feature glues the existing stages;
  it adds no new parse rules. If a node or edge is wrong, the fix belongs in
  F3.2–F3.4, surfaced here by a failing golden diff.
- **Canonical comparison, not byte equality.** Compare via the core's
  canonicalization (stable node/edge ordering by `id`) so a reordering is not a
  spurious failure. Identity is the stable `id`, never structural position
  (`30-ir-spec-v0.md §5`).
- **The golden is committed and authored from the F3.1 manifest**, so it is an
  independent oracle, not a transcript of adapter output. Regenerating it from the
  adapter would defeat the check.
- **Both-green is part of done.** The acceptance demands the React (F2.7) and
  Angular goldens pass *together* in one run, confirming no React-isms leaked into
  the Angular output and the shared IR schema validates both (Rung 4).

Trade-off: an exact-match golden on a tiny fixture is strict by design — any
intended change to extraction must update the golden in the same change. Real-world
tolerance (coverage/sanity rather than equality) is M7's job, not this one.

## 4. Data shapes

This feature defines **no new IR types** — it consumes the shared `UiGraph`,
`GraphNode`, `GraphEdge`, and `Witness` from `30-ir-spec-v0.md` unchanged. Its only
owned artifact is the committed golden `ui-graph.json`, a concrete `UiGraph`
instance (not a new type) with `meta.adapter = "@uigraph/adapter-angular"`,
guarded routes as `may`-edges carrying the guard class name as symbolic `guard`
text (e.g. `"AuthGuard"`, `ruleId: "ng.can-activate"` per `§3`/`§7`), and a static
`witness` on every base edge.

## 5. Test strategy (write these first)

1. **Full extract runs.** `extract('examples/sample-angular-app')` completes
   without throwing and returns a `UiGraph` with `version: 0` and the Angular
   `meta.adapter`.
2. **Golden equality (the core assertion).** Canonical `extract` output equals the
   committed golden — `diff(extracted, golden)` is empty: no added/removed/changed
   nodes or edges, including every edge's `to`, `event`, `guard`, `modality`,
   `source`, `confidence`, and `witness`.
3. **Guard may-edges.** Each `canActivate`-guarded route transition appears as a
   `may`-edge whose `guard` is the guard class name; unguarded transitions are not
   downgraded to `may`.
4. **Witnesses present.** Every `static` base edge carries a `witness` with file
   and `loc`, so the extracted graph passes core `validate` (golden invariant).
5. **Schema/validate clean.** The extracted graph validates against the JSON schema
   (F1.1) and `validate` (F1.3) with zero errors.
6. **Both adapters green together.** A combined run asserts the React golden (F2.7)
   and the Angular golden hold in the same pass and both validate against the one
   core IR schema (Rung 4).

## 6. Self-check / acceptance criteria

- `node scripts/check.mjs` (typecheck + test + lint) is **green** for
  `@uigraph/adapter-angular`.
- `extract` on `examples/sample-angular-app` **matches the committed golden
  `UiGraph` exactly** under canonical comparison (empty golden diff), including
  guard `may`-edges and per-edge witnesses.
- The **React and Angular golden tests pass together** in one run, both validating
  against the single core IR schema — Rungs 3 and 4 closed.
- No framework-specific type or import has leaked below the adapter boundary into
  `@uigraph/core`.

## 7. Soundiness / open questions

- **Non-literal navigations** (computed `navigate`/`navigateByUrl` targets) remain
  over-approximated `may`-edges over the declared route set (F3.3), not `must` —
  the golden encodes them as such; this is declared, not a defect.
- **Guard outcomes are not evaluated.** `canActivate` text is captured for
  legibility only; the adapter never decides whether a guard passes
  (`30-ir-spec-v0.md §6`). The golden reflects guarded transitions as `may`
  regardless of runtime feasibility.
- **A soundiness report** analogous to React's (F2.6) is not required by this
  feature's acceptance; if the Angular adapter emits one, it is informational and
  not part of the golden equality check.
