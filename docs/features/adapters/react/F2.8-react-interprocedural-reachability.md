# F2.8 — React interprocedural (call-graph) reachability

- **Status:** in progress
- **Milestone:** M2 · **Level:** L2
- **Depends on:** F2.3, F2.5 (guard capture), F2.7 (golden)

## 1. Purpose (abstract)

Today's React extractor finds a navigation only when the `navigate(...)` /
`history.push(...)` call sits **directly inside the handler it analyses**
(`analyzeHandler` walks one function body). Real apps route *indirectly*: a
handler calls a helper, a helper calls a shared nav-service, and the literal
route lives two or three calls away from the click. Those transitions are
invisible to a single-body walk — they silently become `unknown`/missing edges,
the exact recall hole the user flagged ("can be wrong but cannot be missed").

This feature adds a **minimal call graph**: from each event-handler entry point
we follow calls into user-defined callees (intra- and cross-file), and mint the
navigation edge when a literal route is reachable through the chain. It is a
Tier‑1 (deterministic) enhancement — it raises *recall* of witnessed edges and
sharpens *guards* — and it doubles as **grounding context for Tier‑2**: the same
reachability summary tells the LLM reviewer which handlers actually reach which
effects, so proposals cite real call paths instead of guessing.

## 2. Contract & boundary

Lives in **`@ui-graph/adapter-react`** (`extract.ts`), never the core — the
interprocedural walk is cohesive with the existing AST helpers (callee
resolution, guard capture, effect detectors), so it stays one module rather than
a thin re-export layer. The core still owns only the opaque IR; it learns nothing
about call graphs. No new IR types — interprocedural navigations produce ordinary
`GraphEdge`s with `source:'static'`, and the witness records the **call path**
(caller→…→sink) as provenance so the edge traces back to lines.

**Exposes** (internal to the adapter):
- `resolveCallee(call, sf) → Node | undefined` — resolve a CallExpression's
  callee to a user-defined function/arrow declaration inside the project: a local
  function, or a named/default import resolved via the existing relative-module
  resolver. Returns undefined for `node_modules`, react-router, and unresolved
  symbols (so the walk never descends into libraries).
- An interprocedural variant of `analyzeHandler` that walks reachable callee
  bodies (bounded by a visited-set + depth cap), binding `navigate`/`history`
  identifiers and literal arguments across the call so a route passed as a
  parameter is still resolved.

## 3. Abstract design

Input: a handler function node + the per-file nav identifiers (`useNavigate`,
`useHistory`). Output: the same `{navCalls, effects}` shape as `analyzeHandler`,
but accumulated across the reachable call graph.

- **Entry points = JSX `on*` handlers** (already resolved by `handlerFnFromAttr`)
  and the top-level component body navigations (already direct).
- **Sinks = navigation calls** (`navigate`/`history.push|replace`) and the
  existing effect detectors (api/state/modal).
- **Edge across a call.** When a body calls a user function, recurse into that
  callee with a derived scope:
  - **nav binding:** if an argument identifier is a known nav/history function in
    the caller scope, the corresponding callee parameter becomes one in the
    callee scope (covers `leaveTo(navigate, '/x')` → `function leaveTo(nav,p){ nav(p) }`).
  - **literal binding:** each parameter is bound to its argument node, so a
    `navigate(path)` whose `path` is a parameter resolves to the literal passed
    in. Intra-file helpers that close over `navigate` need no binding.
- **Guard accumulation.** A guard on the call to the helper (an enclosing `if`,
  `&&`, ternary, success/error branch) is conjoined with any guard on the sink
  inside the helper; non-null guards join as `a && b`. Any guard on the path ⇒
  `may`; a fully unconditional literal chain ⇒ `must`.
- **Termination.** A per-walk visited set of function nodes prevents recursion on
  cycles; a depth cap (5) bounds blow-up. Beyond the cap → a soundiness note, not
  a guess.

## 4. Soundness (golden invariant preserved)

An interprocedural edge is still **deterministically witnessed**: a call chain
ending at a *literal* route is a static witness (provenance = the chain) → `must`
is legitimate. A chain ending at a *computed/variable* route that cannot be
bound to a literal is **never `must`** — it over-approximates to `may` over the
matching routes or is dropped with a soundiness note. The "no edge without a
deterministic witness" rule (`30-ir-spec-v0.md`) holds: the witness's `ruleId`
gains `rr.use-navigate.interprocedural`, and the call path is recorded.

## 5. Test strategy (write first)

In-memory ts-morph projects (mirroring `extract.test.ts`), plus new fixtures in
`examples/sample-react-app`:

1. **Intra-file helper.** Inline handler calls a local `goX()` that closes over
   `navigate` and does `navigate('/x')` ⇒ `must` edge to `/x`. (Single-body walk
   misses it; interprocedural catches it.)
2. **Cross-file nav service.** Handler calls `leaveTo(navigate, '/products')`
   imported from `nav.ts` where `leaveTo(nav,p){ nav(p) }` ⇒ `must` edge to
   `/products` via parameter binding.
3. **Guarded chain.** Helper-call inside `if (isAdmin)` ⇒ `may` edge whose guard
   contains `isAdmin`.
4. **Cycle/depth safety.** Mutually recursive helpers terminate and emit no
   duplicate/phantom edges.
5. **Golden re-baseline.** The sample app's edge counts update to include the new
   indirect navigations; `validateGraph` still returns `[]`.
6. **No node_modules descent.** Calls into react-router/library functions are not
   followed (resolver returns undefined for non-project declarations).

## 6. Self-check / acceptance

- Indirect navigations in the fixtures yield witnessed edges with the correct
  modality (tests 1–3); guards captured across the call (test 3).
- No phantom edges from cycles/library calls (tests 4, 6).
- `validateGraph` clean; golden counts re-baselined (test 5).
- `scripts/check.mjs` (typecheck + lint + tests) green; no framework import leaks
  into `@ui-graph/core`.

## 7. Tier‑2 grounding (precision + evidence)

The reachability map (handler → reachable sinks/effects, with call paths) is
serialized as **grounding context** handed to the Tier‑2 reviewer. Effect:
proposals reference real handlers/effects (`evidenced:true`) and the reviewer can
**prune** hypotheses whose origin handler reaches nothing — raising precision
without lowering the recall-first posture (false positives still allowed, misses
still penalized). The grounding emit is the join point between this Tier‑1 module
and the proposals pipeline (`packages/core/src/proposals.ts`).

## 8. Soundiness / open questions

- **Dynamic dispatch** (callee chosen at runtime, HOFs, method on an interface)
  is not resolved → recorded as a soundiness note, deferred to Tier‑3.
- **Module-singleton routers** (`import history from './history'`) are a separate
  pattern from `useHistory`; only the param-bound and closure cases are in v1.
- **Cross-arg literal flow** is shallow (one binding hop per parameter); deep
  data-flow (a route assembled from several variables) stays `may`/note.
