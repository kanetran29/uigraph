# F2.7 — Validate React adapter against sample golden graph

- **Status:** planned
- **Milestone:** M2 · **Level:** L2
- **Depends on:** F2.6

## 1. Purpose (abstract)

F2.2–F2.6 built the React adapter's parts — route nodes, literal edges,
over-approximation, guard capture, and the soundiness report — each tested in
isolation. This feature is the **trust checkpoint**: it assembles the full
`extract(projectDir)` pipeline and proves the assembled whole, end to end,
reproduces the hand-authored golden graph of `examples/sample-react-app`
*exactly*. It is the rung that lets us claim "the React adapter works" — every
node, edge, modality, source, guard, and witness matches a known ground truth,
not just the per-feature slices.

## 2. Contract & boundary

This lives in the **adapter** `@uigraph/adapter-react`, not core. React/router
knowledge stays here; `@uigraph/core` never learns about it.

**Exposes** — the assembled public entry point of the adapter:

```ts
// Implements the Adapter contract from F0.5 (@uigraph/core).
extract(projectDir: string): { graph: UiGraph; soundiness: SoundinessReport }
```

It wires the F2.2–F2.6 stages into one call and emits the base `UiGraph` plus the
soundiness report. This feature also **owns the committed golden artifact**:
`examples/sample-react-app/golden/ui-graph.json`.

**Depends on:** F2.6 (and transitively F2.2–F2.5) for the pipeline stages;
F2.1 for the fixture and its manifest; `@uigraph/core` for the `UiGraph` type
(`30-ir-spec-v0.md`), `validate()` (F1.3), and `load`/canonical compare (F1.2).

## 3. Abstract design

Input: `examples/sample-react-app` source. Output: a `UiGraph` compared against
the committed golden.

- **Assemble, don't re-derive.** The pipeline is route nodes (F2.2) → literal
  edges (F2.3) → over-approximation (F2.4) → guard text (F2.5) → soundiness
  (F2.6), composed into one `extract`. No new extraction logic is introduced.
- **Golden is authored, then frozen.** The `ui-graph.json` golden is hand-built
  from the F2.1 manifest's known set and committed; the test compares against it,
  so a future regression in any stage is caught as a graph delta.
- **Compare up to canonical ordering.** Node and edge identity is the stable `id`
  (`30-ir-spec-v0.md §5`), not array position. The comparison canonicalizes
  both sides (sort by `id`) before asserting deep equality on every field —
  including per-edge `modality`, `source`, `guard`, and `witness`.
- **Trade-off:** exact-match on a tiny fixture is brittle by design — any
  intended change forces a golden update. That brittleness is the point: it makes
  silent behavior drift impossible. Real-world tolerance is F7's job, not here.

## 4. Data shapes

This feature defines **no new IR types**; the golden is a `UiGraph` per
`30-ir-spec-v0.md`. It owns one local helper concept — a canonical-comparison
result used only by the test harness:

- `GraphMismatch`: `{ kind: 'node' | 'edge'; id: string; field?: string;
  expected: unknown; actual: unknown }` — a field-level delta list so a failure
  names exactly which edge's `guard`/`modality`/`witness` diverged, rather than
  dumping two blobs. `SoundinessReport` is owned by F2.6 and only referenced.

## 5. Test strategy (write these first)

1. **Pipeline runs clean.** `extract('examples/sample-react-app')` completes
   without throwing and returns a `graph` + `soundiness`.
2. **Golden node set matches.** Canonical node set (by `id`) equals the golden's,
   field-for-field (`route`, `componentPath`, `label`, `kind`).
3. **Golden edge set matches.** Canonical edge set (by `id`) equals the golden's,
   asserting `from`/`to`/`event` and the four checkpoint fields per edge:
   **`modality`**, **`source`**, **`guard`**, **`witness`**.
4. **Must vs may per edge.** Literal unconditional navigations are `must`;
   conditional and over-approximated ones are `may` — exactly as the golden says.
5. **Witnesses present and correct.** Every `static` edge carries a `witness`
   with the expected `file`/`loc`/`ruleId`; equals the golden.
6. **Guard text matches.** Each guarded `may`-edge's `guard` equals the golden's
   symbolic source text; unconditional edges have `guard: null`.
7. **Output validates.** `validate(graph)` (F1.3) returns no errors — the
   golden invariant (witnessed base edges) holds on the live output.
8. **Mismatch reporting.** A deliberately mutated golden produces a specific
   `GraphMismatch` naming the diverging `id` + `field`, not just a boolean fail.

## 6. Self-check / acceptance criteria

- `adapter-react` `extract` on `examples/sample-react-app` **matches the
  committed golden `UiGraph` exactly under canonical comparison** — equal node
  and edge sets by `id`, with every edge's `modality`, `source`, `guard`, and
  `witness` field-equal to the golden.
- `validate()` passes on the extracted graph (no witness-less base edge).
- The committed `golden/ui-graph.json` validates against the JSON schema (F1.1).
- The self-healing gate (`scripts/check.mjs`: typecheck + test + lint) is green
  with these tests in the tree — Rung 2 of `50-validation-ladder.md` is closed
  for React.

## 7. Soundiness / open questions

- **Goldens cover the static base only.** Overlay (`manual`) and runtime edges
  are out of scope per `50-validation-ladder.md`; the golden is the static graph.
- **Over-approximated `may`-edges are asserted as authored**, not as "correct
  feasible paths" — exact match means the golden encodes the adapter's declared
  over-approximation (F2.4), and the soundiness report (F2.6) is the honest
  account of what stayed unresolved.
- **Golden maintenance:** the committed graph must be regenerated whenever a
  fixture or ruleset change is intended; an accidental drift correctly fails this
  rung rather than passing silently.
