# F2.9 — Shared-component shells, legible labels, dynamic-target edges

- **Status:** in progress
- **Milestone:** M2 · **Level:** L2
- **Depends on:** F2.2–F2.8
- **Driven by:** validating the adapter against a real production SPA.

## 1. Purpose (abstract)

The golden sample app gives each route its own page component, so the extractor's
"one route → one component" assumptions never strained. The real production app is
a **map-SPA shell**: ten routes (`/`, `/explore`, `/could-buy`, …) all
`render={() => <AppContent/>}`. Running the adapter against it exposed three gaps
that this feature closes:

1. **Shared-component duplication.** A component rendered by N routes was scanned N
   times, minting N copies of its controls/modals (`SignupLoginModal` appeared 11×)
   and N near-duplicate navigation edges. The graph ballooned (77 nodes) and read as
   noise.
2. **Label collision.** Screen nodes labelled by component name, so all ten
   AppContent routes displayed identically ("AppContent"), and the plan-path
   selectors were unusable.
3. **Dynamic-target invisibility.** Production routes with `history.push(redirectUrl)` /
   `navigate(`${location.pathname}…`)` — 74 of them — were recorded only as
   soundiness notes and dropped from the graph. A real transition the planner could
   not see violates the project's "can be wrong but cannot be missed" principle.

## 2. Contract & boundary

All three live in **`@uigraph/adapter-react`** (`extract.ts`); the core IR is
unchanged. The `unknown` node kind and `unknown` modality already exist in
`30-ir-spec-v0.md` — this feature simply starts emitting them.

## 3. Design

- **Per-component-file extraction (dedup).** Compute a representative route per
  component file (the first declared). Both the navigation pass and the controls
  pass process a route only when it is its file's representative, so a shell
  rendered by ten routes is extracted once, attributed to that representative node.
  All route *nodes* still exist (and remain navigation targets); only the redundant
  re-extraction is removed.
- **Label disambiguation.** A component backing exactly one route labels by its
  name (`Home`, `Checkout`); a component shared by several routes labels each node
  by its **route path** instead, so every node is uniquely legible.
- **Dynamic-target edges.** A fully-dynamic navigation target classifies as
  `{kind:'dynamic', expr}` carrying the argument's source text. Instead of being
  dropped, it becomes an `unknown`-modality edge to a per-screen `u_<screen>`
  "dynamic ⋯" sink node, with the symbolic target (or enclosing guard) recorded as
  the edge `guard`. The call is statically witnessed (file/loc, `rr.dynamic-target`)
  — only the destination is undecidable.

## 4. Soundness

The dynamic edge is honest: it asserts only that a navigation *call* exists (proven
by its source location), never *where* it lands — hence modality `unknown`, never
`must`/`may`, and never resolved to a concrete screen. The golden invariant ("no
edge without a deterministic witness") holds: the witness is the call site. Dedup
removes only duplicate extraction, not information — every route node and every
distinct transition survives.

## 5. Tests

In-memory fixtures (`extract.test.ts`):
1. Shared shell: two routes render `Shell`, one renders `C` ⇒ `n_a`/`n_b` label by
   route, `n_c` labels `C`.
2. Dedup: the shared shell's single control is extracted once, parented to the
   representative route; the sibling route has none.
3. Dynamic target: `navigate(dest)` ⇒ a `u_n_a` `unknown` node + an `unknown` edge
   whose `guard` is `dest` and `ruleId` is `rr.dynamic-target`; `validateGraph`
   clean.
4. Negative: an all-literal app emits **no** `unknown` node (the sample app is
   unaffected — golden counts unchanged).

## 6. Result on the reference production app

77→46 nodes (controls 46→19, `SignupLoginModal` 11→2), zero duplicate labels, and
**11 dynamic navigations surfaced** as `unknown` edges (`finalRedirectUrl`,
`inviteId`, `${location.pathname}${location.search}`…) that were previously
invisible — feeding Tier-2 proposals and Tier-3 runtime resolution.

## 7. Open questions

- A shell shared by many routes attributes its controls to one representative; an
  alternative is a first-class "shared component" node the routes alias. Deferred —
  the representative model is simpler and loses no transition.
- Per-screen dynamic sinks keep edges local; if a screen has many distinct dynamic
  targets they collapse onto one sink (the symbolic `guard` still distinguishes
  them). A node-per-target is possible but noisier.
