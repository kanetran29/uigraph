# F2.3 — React literal navigation-edge extraction

- **Status:** planned
- **Milestone:** M2 · **Level:** L1
- **Depends on:** F2.2

## 1. Purpose (abstract)

Turn React's literal navigation idioms into IR edges so the graph shows *how* the app moves between the route nodes F2.2 discovered, not just which routes exist. This feature resolves `<Link>`/`<NavLink> to`, `useNavigate()`/`useHistory().push`, and declarative `<Navigate>`/`<Redirect>` whose target is a string literal into edges over the declared route set. It is the first edge-producing step of the React adapter and establishes the must/may/witness discipline (dossier §4.2, §5.1) that later edge features (F2.4 over-approximation, F2.5 guards) build on.

## 2. Contract & boundary

**Lives in `@uigraph/adapter-react`** (an adapter — React/react-router and ts-morph knowledge belong here, never in `@uigraph/core`, per `docs/40-adapter-contract.md` §6). It contributes the literal-navigation rules to the adapter's `extract` pipeline; it owns no public API of its own beyond those rules.

Exposes (internal to the adapter): a navigation-edge pass consuming the route-node inventory and the shared `TsProject`, emitting `GraphEdge[]` with `source: 'static'`.

Depends on:
- **F2.2** route-node extraction — supplies the node set and route→node-id map that bounds the codomain (no edge points outside it).
- `AdapterContext.tsProject()` / `readFile` (F0.5) for the compiler walk; `GraphEdge`/`Witness`/`Modality` from `@uigraph/core` (F0.4); the sample fixture (F2.1) as ground truth.

## 3. Abstract design

Input: the F2.2 node inventory plus the parsed TS project. Output: `GraphEdge`s, each carrying `event`, `effect`, `modality`, `confidence`, and a static `witness`.

Per idiom: locate the call/JSX site, read its literal target argument (`to`, push arg, `<Navigate to>`/`<Redirect to>`), match it to a route node, and emit an edge from the enclosing component's node to the matched target node. For hook-based navigation (`useNavigate`/`useHistory`) the connecting path — hook call → bound identifier → `.push`/call site — is walked via the compiler API (binding resolution), not text-matched (dossier §59, §184: event-binding → navigate chain).

Key decisions:
- **Modality is set by surrounding control flow.** An unconditional literal navigation is a `must`-edge (`confidence ≈ 1.0`); a literal navigation lexically inside a conditional (`if`/ternary/`&&`/guard render) is a `may`-edge. Only literals reach this feature; non-literals are deferred to F2.4, guard *text* to F2.5.
- **Every edge carries a static witness** (`file` + `loc` + `ruleId`, e.g. `rr.link-to`, `rr.use-navigate`, `rr.navigate-redirect`) — the golden invariant means no edge ships without a source proof.
- **Codomain is the declared route set only.** A literal that matches no declared route is dropped (and noted for F2.6), never emitted as a guessed node.

Trade-off: conditional→`may` is a syntactic, conservative call (we do not evaluate the condition — legibility over decidability, spec §6); this over-approximates certainty downward, which is the sound direction.

## 4. Data shapes

None new. This feature only *populates* the existing `GraphEdge` and `Witness` shapes from `docs/30-ir-spec-v0.md` (`event`, `effect`, `modality`, `source: 'static'`, `confidence`, `witness`). `guard` is left `null` here and filled by F2.5; non-literal fan-out is F2.4. No type is added or extended.

## 5. Test strategy (write these first)

1. **`<Link to="/x">` literal.** A `<Link>`/`<NavLink>` with a literal `to` yields one edge to the matching route node, `event: 'click:Link'`, `modality: 'must'`.
2. **`useNavigate()` literal.** `const nav = useNavigate(); nav('/x')` resolves the binding chain and emits a `must`-edge to `/x` with `effect` noting the navigate call.
3. **`useHistory().push` literal (v5).** `history.push('/x')` emits a `must`-edge with `ruleId: 'rr.use-history-push'`.
4. **`<Navigate>` / `<Redirect>` literal.** Each declarative redirect emits a `must`-edge to its literal target.
5. **Conditional literal → may.** A literal navigation inside an `if`/ternary/`&&` produces a `may`-edge (not `must`) to the correct target.
6. **Witness on every edge.** Every emitted edge has a `witness` with `source: 'static'`, a real `file`, a `loc`, and a `ruleId` — assert none is missing.
7. **Correct codomain.** Each edge's `to` is a node id present in the F2.2 inventory; a literal matching no declared route emits no edge.
8. **Sample-app golden subset.** Running the pass over `examples/sample-react-app` yields exactly the known literal-navigation edges with expected modality and witnesses.

## 6. Self-check / acceptance criteria

- On `examples/sample-react-app`, every literal navigation call site yields an edge to the correct target node.
- Unconditional literals are `must`-edges; literals inside a conditional are `may`-edges.
- Every emitted edge carries a static `witness` (`file` + `loc` + `ruleId`); `source` is `static` on all of them.
- No edge points outside the F2.2 declared route set; no `must`-edge is emitted for a conditional or non-literal target.
- The F0.3 gate (typecheck + lint + test) exits green.

## 7. Soundiness / open questions

- **Non-literal targets are out of scope here** — computed strings, variables, and dynamic dispatch are handled by F2.4 (over-approximated `may`-edges) and reported by F2.6, not silently dropped.
- **Guard text is deferred to F2.5**; this feature sets `guard: null` even on the `may`-edges it creates for conditionals.
- **Binding walk depth is intentionally shallow** — only direct hook-binding→call chains within a component are followed; navigation indirected through a non-literal helper or prop is treated as non-literal (handed to F2.4), an accepted soundiness gap.
