# F1.4 — Sidecar overlay model and merge(base, overlay)

- **Status:** planned
- **Milestone:** M1 · **Level:** L1
- **Depends on:** F1.3 (Invariant validation — golden witness invariant)

## 1. Purpose (abstract)

Manual (and later, agent) edits must never pollute the witness-pure static base graph. This feature establishes the **sidecar overlay** as the sole home for human edits and provides `merge(base, overlay)`, the pure function that produces the *displayed* graph by layering the overlay on top of an untouched base. This is the structural enforcement of the golden invariant (dossier §5.1–5.2): the base on disk stays a deterministic, witnessed artifact, while every manual addition, edit, hide, and annotation lives only in the overlay and is always stamped `source: 'manual'`.

## 2. Contract & boundary

Lives in **`@ui-graph/core`** — fully framework-agnostic, no React/Angular imports.

Exposes one pure function:

```ts
export function merge(base: UiGraph, overlay: Overlay): UiGraph;
```

It reads `base` and `overlay` and returns a *new* `UiGraph` (the displayed graph). It mutates neither input. It does not read or write the filesystem (load/save is F1.2's job) and performs no network or framework work.

**Depends on:** the IR types and the `Overlay` shape from `docs/30-ir-spec-v0.md` (§2), the `merge` semantics defined there (§5), and `validate(graph, overlay)` from F1.3 for the purity/golden invariants. The `Overlay` interface is **owned by the IR spec**, not redefined here.

## 3. Abstract design

**Input:** an unmutated `base: UiGraph` plus an `overlay: Overlay`. **Output:** a fresh merged `UiGraph` representing what the dashboard/MCP display.

Identity is the stable `id` (never structural position). The merge applies four overlay layers, per IR spec §5:

- **addedNodes / addedEdges** — appended to the base's copies. Overlay edges are stamped `source: 'manual'`.
- **editedEdges** — full-replacement edges matched by `id`; the manual edge wins *in the view*, the base record on disk is untouched.
- **removedRefs** — listed base node/edge ids are hidden from the merged result (soft delete); the base still contains them.

**Key decision — immutability by construction:** the function deep-copies base nodes/edges into the result rather than splicing the live arrays, so the caller's `base` object is provably unchanged after the call (acceptance requires this). This trades a copy allocation for a hard guarantee that matches the "base stays pure" rule — the right trade for a non-hot op.

**Key decision — stamping at the boundary:** any overlay-originated edge that reaches the result carries `source: 'manual'`. The merge does not invent witnesses for manual edges; per the IR invariants manual edges are `may`/`unknown`, never `must`, and need no witness.

Scope is exactly the v1 four-layer model above. No conflict-resolution policies, no overlay-on-overlay, no auto-witnessing — those are out of scope.

## 4. Data shapes

This feature **owns no new types**. It consumes `UiGraph`, `GraphNode`, `GraphEdge`, and `Overlay` exactly as defined in `docs/30-ir-spec-v0.md` §2, and implements the `merge` semantics specified in §5 of that document. The `Source` value `'manual'` it stamps is the one declared in §1 there.

## 5. Test strategy (write these first)

1. **Additions appear.** `merge` of a base with an overlay containing `addedNodes`/`addedEdges` yields a result containing those nodes and edges.
2. **Overlay edges are `source: 'manual'`.** Every edge originating from the overlay in the merged result reports `source: 'manual'` (added and edited alike).
3. **Edits replace in the view.** An `editedEdges` entry replaces the base edge with the same `id` in the merged result; matching is by `id`, not position.
4. **Hides apply.** Ids in `removedRefs` are absent from the merged nodes/edges, while still present in the input base.
5. **Base is unmodified (deep).** After `merge`, the input `base` object is deep-equal to a snapshot taken before the call — its arrays, nodes, and edges are byte-equivalent (provably immutable input).
6. **Result is independent.** Mutating the returned merged graph does not retroactively change `base` or `overlay` (no shared references).
7. **Empty overlay is identity-of-content.** Merging an empty overlay yields a graph content-equal to the base (modulo a fresh object).
8. **Fixture merge.** On a small fixture (base = a 3-node static graph, overlay = one added `manual` may-edge + one hide), the merged graph equals the expected combined graph under canonical comparison.

## 6. Self-check / acceptance criteria

- [ ] `merge(base, overlay)` yields the expected combined graph (tests 1, 3, 4, 8 green).
- [ ] The `base` input is **provably unchanged** after merge — deep-equal to its pre-call snapshot (tests 5, 6).
- [ ] All overlay-originated edges in the result report `source: 'manual'` (test 2).
- [ ] `merge` lives in `@ui-graph/core` with zero framework imports.
- [ ] `node scripts/check.mjs` prints `CHECK GREEN` (typecheck + tests + lint, whole workspace); no sibling regression.

## 7. Soundiness / open questions

None for v1. This is a pure core op over fully-resolved IR; it has no dynamic-target or data-dependent-guard exposure (those live in the adapters). Conflict policy (e.g. an `editedEdges` id that also appears in `removedRefs`, or id collisions between `addedEdges` and the base) is deferred to `validate(graph, overlay)` (F1.3), which rejects such overlays before merge; `merge` itself assumes a validated overlay.
