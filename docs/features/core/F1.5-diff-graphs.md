# F1.5 — diff(a, b) over two graphs

- **Status:** planned
- **Milestone:** M1 · **Level:** L1
- **Depends on:** F1.4 (Sidecar overlay model and `merge(base, overlay)`)

## 1. Purpose (abstract)

`diff(a, b)` is the behavioral-change primitive: given two `UiGraph`s it reports exactly which nodes and edges were added, removed, or changed between them, down to per-edge modality and guard changes. It turns the graph into a *lockfile for the app's behavior* (dossier §5.2) so a reviewer can see what a commit did to the transition structure — new flows, dead flows, a `must`-edge downgraded to `may`, a guard rewritten — explained edge by edge rather than as opaque JSON churn. It is the foundation the CLI `diff` command (F4.3) and the MCP `diff` tool (F5.5) expose to humans and agents.

## 2. Contract & boundary

**Lives in `@uigraph/core`** — pure, framework-agnostic, no React/Angular imports, no I/O.

Exposes one pure function:

```ts
export function diff(a: UiGraph, b: UiGraph): GraphDiff;
```

It reads only the public IR shape (`UiGraph`, `GraphNode`, `GraphEdge` from `30-ir-spec-v0.md`) and mutates neither input. **Identity is the stable `id`**, never structural position (§5 of the IR spec). It does not load, save, validate, or merge; callers do that. The CLI and MCP diff features depend on this; nothing here depends on them.

## 3. Abstract design

**Input → output.** Two `UiGraph`s `a` (before) and `b` (after) → a `GraphDiff` of five id-keyed buckets: `addedNodes`, `removedNodes`, `addedEdges`, `removedEdges`, `changedEdges`.

**Classification** (per the IR spec §5):
- **added** — id in `b`, absent in `a`.
- **removed** — id in `a`, absent in `b`.
- **changed** — id in both, but one or more compared fields differ.

For nodes, identical-id nodes are not reported as changed in v1 (acceptance is scoped to add/remove of nodes); only edges carry a per-field change report, since edges are where behavior lives.

**Changed-edge fields.** A `changedEdge` lists the specific fields that differ — `to`, `from`, `event`, `guard`, `modality`, `effect`, `confidence` — each as a `{ before, after }` pair, so a reviewer reads *why* the transition changed. Guard comparison is plain string/`null` equality on the symbolic text; uigraph never evaluates it (legibility over decidability, IR spec §6).

**Key decisions / trade-offs.** Diff is by id, so renaming a node `id` reads as remove+add, not a rename — accepted in v1 (KISS; no rename heuristic). Order-independent and deterministic: outputs are sorted by id so the diff is stable and snapshot-friendly. No structural/semantic equivalence beyond field equality (YAGNI).

## 4. Data shapes

This feature owns the diff result type (the IR types it compares are defined in `30-ir-spec-v0.md` and are **not** redefined here):

```ts
export interface EdgeFieldChange<K extends keyof GraphEdge = keyof GraphEdge> {
  field: K;
  before: GraphEdge[K];
  after: GraphEdge[K];
}

export interface ChangedEdge {
  id: string;
  changes: EdgeFieldChange[]; // non-empty; modality/guard changes appear here
}

export interface GraphDiff {
  addedNodes: GraphNode[];
  removedNodes: GraphNode[];
  addedEdges: GraphEdge[];
  removedEdges: GraphEdge[];
  changedEdges: ChangedEdge[];
}
```

An **empty diff** is all five arrays empty.

## 5. Test strategy (write these first)

1. **Identical graphs → empty diff.** `diff(g, g)` (and `diff(g, clone(g))`) yields all five buckets empty.
2. **Added node.** `b` has a node id absent in `a` → it appears in `addedNodes`, nothing else.
3. **Removed node.** id present in `a`, absent in `b` → `removedNodes`, nothing else.
4. **Added edge.** new edge id in `b` → `addedEdges` only.
5. **Removed edge.** edge id only in `a` → `removedEdges` only.
6. **Modality change.** same edge id, `must` → `may` → one `changedEdge` whose `changes` contains `{ field: 'modality', before: 'must', after: 'may' }`.
7. **Guard change.** same edge id, guard text `"isAuthenticated"` → `"user.role === 'admin'"` → `changedEdge` reports the `guard` field with before/after symbolic text; guard `null` → text and back are both detected.
8. **Endpoint/event change.** changed `to` (or `event`) is reported as a field change, not as remove+add.
9. **Combined seeded delta.** a fixture pair with one added node, one removed edge, and one modality change reports exactly those three deltas and nothing spurious.
10. **Purity & determinism.** neither input object is mutated; bucket contents are sorted by id (stable across input ordering).

## 6. Self-check / acceptance criteria

- `diff` of two identical graphs returns an empty diff (all five arrays empty).
- A graph pair with seeded node add/remove, edge add/remove, and modality/guard changes reports **exactly** those deltas — no missing and no spurious entries.
- Per-edge `modality` and `guard` changes surface as field-level `{ before, after }` entries in `changedEdges`.
- `diff` is pure: both inputs are provably unmodified after the call; output is deterministic regardless of input array order.
- `@uigraph/core` still has zero framework dependencies.
- `node scripts/check.mjs` prints `CHECK GREEN` (typecheck + tests + lint) with no sibling regression.

## 7. Soundiness / open questions

- **No rename detection.** A changed node/edge `id` is reported as remove+add, not a rename. Accepted for v1.
- **No node field-diff.** Changed node attributes (e.g. `label`, `route`) on a stable id are not reported in v1; only nodes added/removed and edges field-changed. Revisit if a consumer needs node-level change reporting.
- **Float confidence equality.** `confidence` is compared by strict equality; no epsilon tolerance. Adequate while confidences are fixed constants; revisit only if computed confidences introduce noise.
