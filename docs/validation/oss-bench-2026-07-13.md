# OSS extraction bench — 10 well-known apps (2026-07-13)

`uigraph map --controls` run against ten widely-known open-source apps, one
adapter auto-detect per app, no per-app tuning. Purpose: robustness + recall
smoke test of the static extractors on real-world code, and an honest census
of where extraction degrades — and whether it degrades *loudly* (soundiness /
warnings, per the adapter contract) or *silently* (the only true failure).

## Topline

- **10/10 crash-free**, all under 10s, adapters auto-detected correctly every time.
- **4/10 good**, **3/10 honest degradation** (gaps flagged via soundiness/warnings, per contract), **2/10 silent misses** (contract violations — the only real failures), **1/10 defensible-zero that should be louder**.

## Findings for the extractor backlog (ranked)

1. **vue: `router.addRoutes()` / exported route arrays merged at runtime** —
   vue-element-admin's `asyncRoutes` sits statically in the same file the
   adapter parses, yet none of it is extracted and nothing is flagged. Fix =
   collect all exported route arrays (not just the one passed to
   `createRouter`/`new Router`), or at minimum emit a soundiness note when an
   `addRoutes`/`addRoute` call is seen. *Silent-miss class.*
2. **react: route paths built by helper functions / template-literal
   constants** — Outline's `draftsPath()`-style path builders and
   `` `/doc/${slug}` `` constants drop whole routes unflagged. Fix = resolve
   single-return string helpers + template-literal prefixes for route `path`
   props (the nav-target side already does prefix fan-out; the route side
   does not). *Silent-miss class.*
3. **angular: data-driven nav via menu-item arrays** — ngx-admin navigates
   exclusively through `NbMenuItem[].link` data consumed by a library
   component. Common across Angular admin templates. Fix = a targeted
   `menu-data-nav` soundiness note (recall the paths as `may` candidates or
   proposals), instead of only the generic no-edges warning.
4. **next/react: shared-layout `<Link>` edges** — Commerce's navbar/footer
   links live in shared components and surface as one `layout-nav` note
   rather than per-screen `may` edges (the Next layout-chain pass exists;
   extend attribution to shared non-layout components).
5. **react: emit an explicit "no routes found" soundiness note + an entry
   node** when a detected react app yields an empty graph (Excalidraw case),
   so zero is visibly a verdict, not an absence.

## Method notes

Legacy RealWorld/TakeNote workspaces had lost their source clones (prior
session scratchpads); sources were restored into the workspace dirs and
re-mapped fresh — numbers above are from today's runs. All ten workspaces are
registered, so every app is browsable in the dashboard switcher.
